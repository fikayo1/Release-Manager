# Release Manager — design context (`.impeccable.md`)

> **Placement note:** acceptance criterion C6 expects this file at the
> release-manager **repository root**. It is committed here under `frontend/`
> because this build phase may only write inside `frontend/` (and a few named
> files). A follow-up may `git mv frontend/.impeccable.md .impeccable.md`.
> The content is authoritative regardless of location.

## Audience

Release managers and engineering teams who need **confidence and auditability**
in a governed GitHub release. They arrive with a specific question ("is this
safe to ship, and who approved it?") and expect the interface to answer with
evidence, not decoration. Secondary audience: an operator wiring the service up
for the first time.

## Tone

Bold editorial, precise, calm, evidence-forward. Restrained neumorphism: soft
extruded surfaces and low-contrast shadows, never skeuomorphic excess. The page
should read like a well-set report — generous headings, quiet chrome, one
decisive accent.

## Typography pairing

Both faces ship through the platform font stack — **no webfont download, no
build-time font fetch, no new npm dependency** — so the build stays fully
offline and deterministic.

| Role | Token | Stack | Usage |
| --- | --- | --- | --- |
| Display / headings | `--font-display` | `"Iowan Old Style", "Palatino Linotype", Palatino, "Book Antiqua", Georgia, "Times New Roman", serif` | `h1`–`h3`, the wordmark, hero copy. Weight 600–700. Tight leading (1.1–1.2). |
| Text / UI | `--font-text` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` | body, labels, buttons, tables, nav. Weight 400 body / 600 emphasis. Leading 1.5. |

Fluid type scale (clamped): body `clamp(0.95rem, 0.9rem + 0.3vw, 1.05rem)`;
`h1` `clamp(1.9rem, 1.5rem + 2vw, 2.9rem)`; `h2` `clamp(1.3rem, 1.1rem + 1vw, 1.7rem)`.
Fallback stacks above are the actual delivered fonts on most operator machines;
the design does not depend on any single face being present.

## Neumorphic token set

| Token | Value | Meaning |
| --- | --- | --- |
| `--surface` | `#e8ebf1` | Base app surface (also the body background). |
| `--surface-raised` | `#eef1f6` | Cards, sidebar, raised controls. |
| `--surface-inset` | `#e0e4ec` | Wells: inputs, code blocks, the active-nav trough. |
| `--shadow-dark` | `rgba(26, 35, 56, 0.20)` | Lower-right ambient shadow. |
| `--shadow-light` | `rgba(255, 255, 255, 0.92)` | Upper-left edge highlight. |
| `--raised` | `-6px -6px 14px var(--shadow-light), 6px 6px 16px var(--shadow-dark)` | Standard extrusion for cards / buttons. |
| `--inset` | `inset 2px 2px 6px var(--shadow-dark), inset -2px -2px 6px var(--shadow-light)` | Pressed / well treatment. |
| `--radius-1` / `--radius-2` / `--radius-3` | `8px` / `14px` / `22px` | Controls / cards / hero + sidebar. |

**Elevation rules:** at most one raised level on screen at a time — a raised card
does not contain further raised cards; nested emphasis uses the inset well
instead. Shadows never exceed the pairs above (no dark, hard drop shadows).
Reduced-motion users get the same surfaces with no transition.

## Gold accent token

| Token | Value | Notes |
| --- | --- | --- |
| `--accent-gold` | `#c9a227` | The visible gold. Used as a **fill** behind dark ink. |
| `--accent-gold-ink` | `#6f520c` | Text-weight gold for the active nav label / links on the light surface (≥ 4.5:1). |
| `--accent-gold-ring` | `rgba(201, 162, 39, 0.65)` | Focus ring / selection highlight. |

**May appear on:** the primary button fill (`Scan now`, `Approve and publish`,
`Continue with GitHub`, the marketing primary CTA), the active sidebar item
(gold inset trough + `--accent-gold-ink` label + gold edge), and
`:focus-visible` rings / `::selection`.

**Must not appear as:** small body text on the surface at `--accent-gold`
(too low contrast — use `--accent-gold-ink`), large low-contrast gold-on-white
fills, or more than one gold call-to-action competing in a single view.

## Spacing scale

`--space-1: 0.35rem` (icon gaps, tight stacks) ·
`--space-2: 0.6rem` (control padding) ·
`--space-3: 1rem` (default block rhythm) ·
`--space-4: 1.5rem` (card padding, section gaps) ·
`--space-5: 2.5rem` (page gutters, hero padding).
Vertical rhythm is a multiple of `--space-3`; never hand-tune a one-off margin.

## Accessibility rules

- **Contrast — WCAG 2.1 AA.** Body text `--ink #1b2330` on `--surface` ≈ 13:1.
  Secondary text `--ink-soft #454f63` ≥ 7:1. Primary button: `--ink` on
  `--accent-gold #c9a227` ≈ 6.4:1. Active-nav label `--accent-gold-ink #6f520c`
  on `--surface-inset` ≥ 4.5:1. Large text / UI borders ≥ 3:1.
- **Focus.** Every interactive element shows a visible `:focus-visible` ring
  (`0 0 0 3px var(--accent-gold-ring)`), never `outline: none` without a
  replacement.
- **Targets.** Every interactive target is ≥ 24 × 24 CSS px, including on mobile
  (kept from the prior globals rule).
- **Motion.** `@media (prefers-reduced-motion: reduce)` disables the skeleton
  animation and all sidebar / hover transitions.
- **Landmarks.** One `<nav aria-label="Dashboard sections">` in the sidebar and
  one `<main>` per authenticated page; marketing and login pages own a single
  `<main>`. The active link carries `aria-current="page"`.
- **Sidebar toggle.** On ≤ 600px the toggle is a real `<button>` with
  `aria-expanded` and `aria-controls` pointing at the nav region; `Esc` and a
  backdrop click close it and return focus to the toggle.
