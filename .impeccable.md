# Release Manager — design context

## Audience

Release managers and engineering teams who need confidence and auditability in
a governed GitHub release. The interface should answer “is this safe to ship,
and who approved it?” with evidence rather than decoration.

## Tone

Bold editorial, precise, calm, and evidence-forward. Use restrained
neumorphism: soft extruded surfaces and low-contrast shadows, never excessive
skeuomorphism. The product should read like a well-set operational report with
quiet chrome and one decisive accent.

## Typography pairing

- **Display/headings:** `"Iowan Old Style", "Palatino Linotype", Palatino,
  Georgia, serif`; weight 600–700 with tight leading.
- **Text/UI:** `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`;
  weight 400 for body and 600 for emphasis.

Use a fluid scale on marketing pages and a stable readable scale in the
dashboard. Do not require web-font downloads or new runtime dependencies.

## Neumorphic token set

| Token | Value | Purpose |
| --- | --- | --- |
| `--surface` | `#e8ebf1` | App background |
| `--surface-raised` | `#eef1f6` | Cards and sidebar |
| `--surface-inset` | `#e0e4ec` | Inputs and active-nav wells |
| `--shadow-dark` | `rgba(26,35,56,.20)` | Lower-right ambient shadow |
| `--shadow-light` | `rgba(255,255,255,.92)` | Upper-left highlight |
| `--radius-1/2/3` | `8px / 14px / 22px` | Controls, cards, hero/sidebar |

Use one elevation level at a time; nested emphasis uses an inset well rather
than another raised card. Respect reduced-motion preferences.

## Gold accent

`--accent-gold: #c9a227` is the single visible accent. Use it for primary
actions, the active sidebar item, focus rings, and selection. Pair it with
dark ink (`--accent-gold-ink: #6f520c`) where text is required; never use
small low-contrast gold text on a light surface.

## Accessibility rules

- Meet WCAG 2.1 AA: body text and headings have at least 4.5:1 contrast.
- Every interactive element has a visible `:focus-visible` ring and a minimum
  24 × 24 CSS-pixel target.
- Dashboard navigation uses a labelled sidebar nav and `aria-current`.
- Marketing/login pages use one main landmark; the responsive sidebar toggle
  exposes `aria-expanded` and closes with Escape/backdrop interaction.
- Do not remove functional loading, error, keyboard, or mobile behavior while
  applying the visual system.
